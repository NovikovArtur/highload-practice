# ДЗ 1. Платежная система, тема 15

Сервис принимает платежи покупателей через внешнего платежного провайдера, оформляет возвраты и выплачивает деньги продавцам. Расчетная нагрузка: 1 млн платежей в сутки, до 300 новых платежей в секунду на пике.

## Роли

| Роль | Действия |
| --- | --- |
| Покупатель | Оплачивает заказ и проверяет результат. |
| Продавец | Создает платежи, смотрит статусы, оформляет возвраты и выплаты. |
| Оператор | Сверяет операции с провайдером и разбирает ошибки. |
| Платежный провайдер | Проводит операции и сообщает их результат. Внешняя система. |

## Сценарии и требования

Главный сценарий: S1, прием платежа. Значения p50, p95 и p99 указаны в миллисекундах.

| Сценарий | Функциональное требование | p50 | p95 | p99 |
| --- | --- | ---: | ---: | ---: |
| S1. Прием платежа, главный | Продавец создает платеж. Сервис сохраняет его и выдает ссылку на оплату. Успех фиксируется после подтверждения провайдера. | 200 | 600 | 1200 |
| S2. Подтверждение платежа | Сервис проверяет сообщение провайдера, записывает статус и сумму, уведомляет продавца. Повтор сообщения не создает вторую запись. | 150 | 500 | 1000 |
| S3. Проверка статуса | Покупатель и продавец получают текущий статус доступного им платежа. | 80 | 250 | 500 |
| S4. Возврат | Продавец запрашивает полный или частичный возврат. Сервис резервирует сумму и передает запрос провайдеру. Общая сумма возвратов не превышает сумму платежа. | 250 | 700 | 1500 |
| S5. Выплата | Продавец запрашивает выплату. Сервис резервирует доступный остаток и передает запрос провайдеру. Одна сумма не выплачивается дважды. | 300 | 900 | 2000 |

## Остальные нефункциональные требования

| Требование | Значение |
| --- | --- |
| Измерение задержки | Для S1, S4 и S5 измеряется время до ответа о принятии запроса. Для S2 время от получения сообщения провайдера до записи статуса. Для S3 время ответа API. Работа провайдера в эти значения не входит. |
| Доступность | API создания платежа и проверки статуса: 99,95% за месяц. API возвратов и выплат: 99,9% за месяц. |
| Сохранность | Финансовые записи сохраняются до ответа клиенту. При отказе одной зоны RPO 0, RTO до 15 минут. При отказе региона RPO до 5 минут, RTO до 4 часов, затем обязательна сверка с провайдером. |
| Согласованность | Статусы, баланс и резервирование средств согласованы сразу. Запросы к сервису и провайдеру используют ключ идемпотентности. Неизвестный результат не считается успешным. |
| География | Один активный регион с тремя зонами, второй регион для восстановления. После сбоя региона выплаты возобновляются только после сверки. |
